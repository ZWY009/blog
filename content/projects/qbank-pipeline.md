## 问题

题库和笔试真题散落在各种网页里，结构各不相同，还夹着大量重复题和失效图片。人工整理几十套题，既慢又容易漏。

## 拆成三段

这个项目最关键的决定是**不把它写成一个脚本，而是拆成三个可独立重跑的阶段**：

**① 采集（浏览器适配器）**
用 ego-browser 复用已登录的会话去取数——很多题库要登录才能看，纯 HTTP 抓取拿不到。每个站点写一个适配器，只负责"怎么从这一页拿到结构化的题"，其余不管。

**② 清洗（Python 管线）**
去重、按岗位归类、图片本地化（外链图片会失效，必须落盘）、字段归一。这一段是纯函数式的转换，输入原始 JSON，输出干净数据集。

**③ 成书（Typst 排版）**
数据集 → Typst 源文件 → PDF。用 Typst 而不是 Word/LaTeX，是因为它编译快、纯文本可版本控制、排版规则能写成代码。

## 为什么这样拆

采集最容易坏（页面一改就挂），清洗和排版不受影响。三段之间只有 JSON 一种接口，所以**采集挂了可以只重跑第一段**，不用从头再来。

把易变的部分和稳定的部分隔开，是这类数据流水线最重要的一件事。

## 技术栈

Python 做主流水线，ego-browser 做需要登录态的采集，Typst 做最终排版。
